## 1. Ruling: the shared finite kernel already exists

The earlier multi-problem program was written as if the next shared milestone might be to **build** a new generic finite/uniform bridge kernel. The Toledo + Readout Genesis audit changes that priority.

The reusable architecture is already present in the registered programme:

```text
Retention
  -> Structure
  -> Translation q_D
  -> Sufficiency / dynamic closure
  -> Readout
  -> Invariant + defect
  -> PASS / FAIL / UNRESOLVED
  -> bounded claim
```

Therefore the default Clay workflow is now:

```text
Clay question
  -> Toledo lookup across all 8 domain buckets
  -> Genesis compatibility check
  -> reuse existing root / reading / verifier object
  -> derive only the missing domain adapter
  -> register that genuinely new adapter as PROPOSAL
```

and **not**:

```text
Clay question
  -> invent a second generic finite framework
  -> duplicate state / quotient / defect / verifier machinery
```

This is the practical application of `TG-RFG-01`:

```text
Toledo lookup
  -> Genesis compatibility
  -> reuse existing object
  -> derive only missing piece
  -> mark PROPOSAL
```

## 4. Cross-domain registered families that are reusable only by exact translation

The audit also found several later Toledo/Genesis families whose **formal shape** is potentially useful across Clay lanes. They must be reused by exact object matching, never by semantic analogy alone.

### 4.1 Discrete causal calculus / FTCC

The registry contains a discrete causal derivative on a causal-delay graph together with a finite-path fundamental theorem and a path-independence converse. This is candidate shared infrastructure for finite transport / telescoping / path-consistency arguments.

**Reuse condition:** the Clay adapter must identify the finite graph, edge delay/weight semantics, and invariant being transported. Do not import continuum conclusions from the name “causal calculus”.

### 4.2 `L_R` spectral / graph-energy family

Toledo contains finite graph-Laplacian structure, PSD/energy facts, spectral ceilings and retained spectral machinery.

**Reuse condition:** the target Clay object must be shown to factor through the same retained finite operator or through a documented reading of it. A spectral analogy is not a proof of such a factorization.

### 4.3 Occupation / count quotient and lineage

Registered chemistry/formal-composition work contains the pattern:

```text
equal occupation data
+ equal registered readout/successor signatures
=> exact factorization through the quotient
```

and keeps lineage/provenance distinct from mere counts.

**Reuse condition:** use this as a quotient theorem pattern only after proving that the chosen Clay event/certificate state has the required successor/readout signature property. Do not infer dynamics from equal counts alone.

### 4.4 Theta / endogenous geometry

Genesis includes a root-extension lane in which relational geometry is generated/read from retained structure rather than assumed as a semantic label at the root.

**Reuse condition:** a Clay adapter must specify what retained distinctions induce the geometry and must preserve the no-early-collapse / lineage gates. “Geometry is endogenous” is architecture, not a Clay theorem.

### 4.5 Gauge / loop / holonomy families

Physics/relativity/quantum readings contain finite loop, connection, curvature, normalization-holonomy and gauge-invariance structures.

**Reuse condition:** holonomy types are typed. A projective-lineage holonomy, scalar phase holonomy, gauge holonomy, and normalization holonomy are not interchangeable without an explicit registered bridge. The Navier–Stokes Type-P / Type-Phi audit is a standing warning against this mistake.

## 5. Revised six-lane Clay map: reuse first, adapters only

The project should now be organized as one registered kernel plus six domain adapters.

### 5.1 Navier–Stokes — direct active lane

**Already reusable:**

- Genesis/Toledo state, dynamic-closure, sufficiency, lineage, no-silent-loss and claim-boundary objects;
- existing finite Fourier/Galerkin and exact triad machinery in this repository;
- current retention-gap / readout architecture;
- exact finite obstruction and fail-closed checker infrastructure.

**Current Git-grounded bottleneck:** merged PR #68 records that the recurrence chain from the retention-gap inequality is derived, while:

- the energy-only recent-remainder route is refuted as stated;
- the solution-dependent remainder is `REGULARITY-EQUIVALENT / HOLD`;
- a constructive generator of the genuinely weaker remainder remains `OPEN`;
- Clay regularity remains `OPEN`.

**Missing adapter, not missing generic kernel:**

```text
finite registered NSE structure
  -> solution-independent scale-uniform constructive remainder / progress law
  -> retention-gap contraction
  -> explicit regularity continuation bridge
```

No second universal finite framework should be created to attack this gap.

### 5.2 P vs NP — direct active lane

**Already reusable:**

- finite state / candidate / defect / verifier architecture;
- retention/recompute/resolve and no-collapse discipline;
- exact local defect and robust-margin patterns;
- finite obstruction and hitting/capture abstractions already developed in `information-discrete-math` PR #117.

**Current Git-grounded bottleneck:** PR #117 isolates the remaining premise as an unrestricted direct-sample / hitting-support constructor for undersized circuits. In ADC language one needs a constructible candidate-adaptive support with inverse-polynomial capture probability, without hidden SAT/equivalence/MCSP power.

**Missing adapter, not missing generic kernel:**

```text
undersized unrestricted circuit
  -> efficiently constructible locally verifiable defect support
  -> SAT notin P/poly
  -> P != NP
```

The first arrow remains `OPEN` and is essentially the circuit-lower-bound breakthrough.

### 5.3 Yang–Mills + mass gap — candidate third direct lane

**Reusable registered machinery:**

- finite state/dynamics/readout gates;
- symmetry quotient discipline;
- gauge / connection / loop / holonomy families;
- finite spectral-energy machinery;
- cross-resolution/bridge-error discipline;
- Theta-style endogenous geometry when an exact finite relational encoding is proved.

**Missing domain adapters:**

1. exact finite gauge configuration encoding with a justified gauge quotient;
2. refinement/scale maps preserving declared observables;
3. a finite spectral-gap certificate with a scale-uniform positive lower bound;
4. a constructive continuum/QFT bridge proving that the retained finite gap is the Clay mass gap.

Until those are specified and proved, Yang–Mills remains a candidate lane, not a Clay-level result.

### 5.4 Riemann Hypothesis — exploratory/supporting lane

**Reusable registered machinery:**

- finite spectral / retained-eigenvalue tools;
- exact interval/margin and fail-closed verification patterns;
- path/extension consistency architecture;
- finite obstruction / claim-ceiling discipline.

**Missing domain adapter:**

```text
off-critical zero
  -> finite detectable structural obstruction
```

or an equivalent all-height propagation theorem. Finite zero verification by itself is not the missing theorem.

### 5.5 Birch–Swinnerton–Dyer — exploratory/supporting lane

**Reusable registered machinery:**

- independent readouts of one retained object;
- exact quotient/sufficiency gates;
- finite exact arithmetic and provenance patterns;
- invariant-preserving translation / bridge-error discipline.

**Missing domain adapter:** a generic theorem, for every admissible elliptic curve, that forces the arithmetic and analytic readouts to encode the same relevant invariant at the required order/rank level.

Agreement on finite datasets is evidence only, not BSD.

### 5.6 Hodge Conjecture — exploratory/supporting lane

**Reusable registered machinery:**

- finite candidate/witness verification;
- symmetry quotient / exact algebraic certificate patterns;
- obstruction / sufficiency / no-collapse gates;
- exact provenance and bounded-claim discipline.

**Missing domain adapter:** a generic representability/obstruction theorem connecting an admissible Hodge class to an algebraic-cycle witness in the required rational setting.

Finite positive instances do not supply the universal bridge.

## 6. What is no longer a priority

The following should **not** be treated as primary research tasks unless a concrete missing adapter forces them:

- creating another generic finite state tuple;
- creating another generic quotient/dynamic-closure definition;
- creating another PASS/FAIL/UNRESOLVED layer;
- creating another generic bridge-defect object;
- creating another universal “finite certificate kernel” whose role is already covered by Genesis/Toledo;
- running larger finite computations without naming the exact `OPEN` adapter they test;
- importing a theorem from one Toledo domain merely because its wording is analogous.

A new generic theorem is justified only when Toledo lookup returns no usable registered object and the theorem materially closes more than one current adapter gap.

## 7. New execution priority

The earlier priority “build a Finite Uniform Bridge Kernel” is superseded by the following.

### P0 — Registry-first audit at every theorem step

Before using or deriving any equation:

```text
Toledo lookup
-> inspect status/tier/lineage
-> check Genesis admissibility
-> reuse or declare NOT REGISTERED
```

### P1 — Close the two load-bearing direct-lane adapters

**Navier–Stokes:** construct a genuinely weaker, solution-independent scale-uniform recent-remainder/progress law strong enough to feed the already-derived retention-gap recurrence.

**P vs NP:** construct the unrestricted candidate-adaptive defect/hitting support required by PR #117 without a hidden semantic oracle.

These are mathematically different adapter theorems. They share governance and finite-certificate infrastructure, not a claimed reduction between the problems.

### P2 — Promote only genuinely shared missing lemmas

If work on NS or P vs NP produces a theorem that is domain-independent **and is absent from Toledo**, register it once in the shared theorem kernel / Toledo proposal lane, then instantiate it back into both domains.

### P3 — Open Yang–Mills only through an explicit adapter contract

Do not begin simulation-first work. First define the exact finite gauge state, quotient, refinement map, spectral-gap readout, and final bridge obligations.

### P4 — Use RH/BSD/Hodge as probes, not as claim multipliers

Use them to test whether a generic registered theorem really transports across domains. Keep each lane `EXPLORATORY` until a domain-specific obstruction/bridge theorem is identified.

## 8. Adapter card required for all future Clay work

Every new Clay-facing theorem or experiment should name exactly one adapter card:

```yaml
adapter_card:
  clay_problem: <NS | PNP | YM | RH | BSD | HODGE>
  target_claim: <exact bounded statement>
  toledo_objects_reused:
    - <codes>
  genesis_gate:
    - <sufficiency / dynamic closure / lineage / bridge rule>
  missing_piece: <one exact mathematical obligation>
  status: <DERIVED | OPEN | REFUTED | HOLD | PROPOSAL | finite_diagnostic>
  falsifier: <what would refute this route>
  bridge_to_clay: <explicit final semantic adapter or OPEN>
```

If `missing_piece` is blank, the work is not attacking a Clay bottleneck.

If `toledo_objects_reused` is blank without a documented lookup result, the work fails `TG-RFG-01`.
